# DERP 圆心布局 v6

将真实 DERP 服务器从外圈移动到圆心，不新增或复制设备。当前本机 DERP 地图中 `tencent-sh / 901 / 901a` 指向 `[IP 已隐藏]:8443`；其宿主通过已核对的 Node ID 绑定到 `vm-0-4-opencloudos`。服务器保持存储体积比例，以金色信标区分基础设施角色。

## 运行配置

在实际 `observer.config.json` 中增加可选字段并重启观察后端：

```json
{
  "tailscale": {
    "binary": "/opt/homebrew/bin/tailscale",
    "centralRelayRegion": "tencent-sh",
    "centralRelayNodeId": "nr1SAGTkH711CNTRL"
  }
}
```

其他环境应填写实际中继地区与服务器 Node ID。此字段只控制观察与展示，读取本机 `tailscale status --json` 和 `tailscale debug derp-map`，不修改 Tailscale 配置或转发数据。未配置时保留原有分布式圆环。

## 几何与连接含义

- `N` 仅包含外圈设备；`R = N × 16 / (2π)`，加入设备后等距重排。当前 13 台设备中，1 台位于圆心，12 台外圈设备的半径约为 `30.5577`。
- 中继圆心坐标固定为 `[0, 0.3, 0]`。外圈共用角速度及暂停时钟，圆心可以自转但不参与公转。
- 金色连接按本机 → 中继 → 远端设备绘制；蓝色为本机 → 设备的直连。重复的中继段合并绘制。相同画面线段同时承载两种连接时，优先显示金色，数量仍按实际连接统计。
- `Relay` 首选地区不能单独证明中继路径：活动连接具有 `CurAddr` 时为直连；离线、闲置、设备中继另行保留。无法确定具体 DERP 实例时不画确定的中继段。
- 只知道本机到各设备的路径，不据此补全远端设备之间的实时网络、物理 LAN 归属或速度。对等全连接关系仍是淡线示意。
- 只读命令失败后保留已知中继身份与位置，移除实时路径并标为未知。未明确关联设备身份时不猜测圆心。
- 拥挤总览以紧凑名称显示外圈设备，选中时展开完整信息；设备标签避让中继图例与存储图例。
