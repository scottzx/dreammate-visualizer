# 戴森球模型与物理内存比例（历史记录）

**口径已更正**：用户随后明确要求按设备存储总容量决定大小。当前实现见 [设备存储与球体比例](storage-sizing-v6.md)；本页保留旧版 RAM 实现与验收过程，不代表当前采集口径。

本轮目标：参考用户提供的《戴森球计划》画面，采用小型发光恒星、通透球壳、细骨架、零散采集面板和倾斜粒子环；用户已确认内存减半对应体积减半，半径缩至约 79.37%。

## 实现

- 共享模型修订号 `dyson-lattice-v3.1`。两种设备模型均以归一化半径制作：提供暖金和冷蓝两种复用素材，尺寸使用同一内存比例；当前对等圆环统一使用冷光素材。单个 GLB 约 396 KiB、10 个网格；几何、材质和轨道中继可独立加载、旋转及导出。
- 恒星半径 0.27、外壳半径约 1.02。外壳由细经纬骨架和不规则留空面板组成；移除厚装甲、大面积扫描底盘和粗约束环。场景增加随暂停时钟冻结的确定性粒子环、中心光晕与窄光芒。星舰、尾焰和巡航高度随所在设备半径变化。
- 半径 `r = 1.8 × cbrt(RAM / 64 GiB)`；64G、128G、256G、512G 的半径约为 1.8、2.268、2.857、3.6，体积比 1:2:4:8。没有主星加成、服务加成或列表归一化。
- 标签与设备详情显示内存和来源。用户追加确认：未知或无效内存统一按 128G 显示，半径约 2.267858，并标记默认；真实内存字段保持未知，后续采集成功自动替换。缓存保留原数值和观测时间。详见 [数据接入](data-sources.md#物理内存与星球体积)。
- 本机 Mac 通过显式原生 Node ID 绑定采集到 16 GiB。其他 Node 当前没有返回硬件内存字段，也未找到匹配的只读硬件能力，显示侧统一默认 128G，并明确标注默认值。演示模式提供 8、64、128、256、512 GiB 的独立示例，不写入真实设备。

## 验证与工件

本轮同目录有圆环布局任务并行修改公共场景。最终验证采用两者汇合后的代码，不覆盖其设备组织规则。合并后 55 项测试、TypeScript 与生产构建通过；补充覆盖同 URL 更换设备、manifest 失败/不完整、技能目录失败/分页失败的身份隔离回归。

独立模型与内存评审确认外观及体积比例符合要求，发现两项缓存身份隔离问题，已修复。另一个全新上下文的独立复验执行 47 组情境通过，报告为 `artifacts/dyson-v5/memory-fix-review.md`。用户追加的默认 128G 规则通过单测与最终浏览器回归验证；它是显示回退值，不改写硬件观测数据。

桌面 1280×720 的浏览器实际半径：8G→0.9、64G→1.8、128G→2.2678578898、256G→2.8573218935、512G→3.6。Mac 16G 的详情显示“观察机实测”。已选 Mac 拉远到 5000 时投影半径 0.153px，所有名称卡片隐藏。

暂停两次整页截图在固定核心区域（280×280）差异为 0 像素，时钟均为 206.602；减少动态偏好下两次时钟均为 206.552、effects-running=false。局部截图曾遇到采集重绘空白，保留为 diagnostic 文件，未作为冻结验收依据。

390×844 的开发页面保持 1145.77×644.5 舞台；详情 HUD 位于 x38–382，实操滚动后能完整看到物理内存与来源。桌面最终验收来自 Tailscale 生产地址，浏览器无 error，health 返回 200。物理手机手势、持续帧率、其他设备真实 RAM 的生产上报未验证。
